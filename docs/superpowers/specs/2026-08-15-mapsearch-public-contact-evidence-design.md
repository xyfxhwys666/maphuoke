# MapSearch 公开联系方式证据发现设计

## 目标

为高德已采集企业联系方式补充独立公开网页证据，作为 MapSearch 的可选质量增强。公开网页核验不影响 TaGeAI 消费已完成高德采集结果。

## 范围

- 扩展 `PublicEvidenceVerifier.verify_contact()` 的证据来源发现。
- 复用已有公开搜索结果 HTML 解析器，不改桌面端、ERP 或高德浏览器采集流程。
- 已完成高德采集的线索可直接进入 MapSearch 全局结果池；已升级线索保留更强的来源证据。

## 流程

1. 先按现有方式抓取 `source_urls`，验证企业名与联系方式是否同页出现。
2. 未命中时，以精确企业名加“联系方式”查询固定公开搜索入口。
3. 从搜索结果中最多提取 5 个 HTTP(S) 候选页面，跳过搜索引擎自身页面、重复链接和无效 URL。
4. 逐页抓取可见文本；企业名规范化后必须匹配，且手机号数字串或邮箱必须精确匹配。
5. 命中时返回 `verified_public_web`、来源 URL 与最小必要引用；所有页面未命中或访问失败时保持 `captured`。

## 安全与质量约束

- 不登录、不读取 Cookie、不绕过验证码或访问控制。
- 不把搜索结果标题、摘要或高德已采集号码本身当作核验证据。
- 只使用固定公开搜索入口发起发现请求；候选页必须是 HTTP(S) URL。
- 单次核验最多访问 5 个发现页面，失败按 best-effort 处理，不阻塞采集任务。
- 不因公司名相似、地址相似或行业相似升级；必须同页精确匹配企业名和联系方式。

## 验收

- 已有来源页未含联系方式、但公开候选页同时含企业名和同一手机号时，返回 `verified_public_web`。
- 候选页仅有企业名、仅有联系方式、企业名不同或联系方式不同，均保持 `captured`。
- 无候选页或候选页请求异常时不抛出未处理异常、不生成虚假结果。
- 公开核验成功后，连接器只返回该已核验结果；未成功的已采集结果仍不可见。

## 历史任务回填

提供 `tools/refresh_public_evidence.py` 用于分批重核验既有任务。它只处理已存储且联系方式未核验的线索，不创建采集任务、不刷新高德、不读取会话、不投递 ERP。运行时必须显式指定任务 ID 和最大处理条数，输出仅包含处理统计。
