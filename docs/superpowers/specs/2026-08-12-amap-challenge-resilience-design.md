# 高德验证触发降频与断点保护设计

## 目标

降低高德网页搜索触发滑块验证的概率，并确保验证或异常页面出现时，采集任务立即暂停且保留当前工作单元，避免把验证后的搜索批量误判为无结果。

## 约束

- 不自动识别、拖动或绕过高德滑块验证。
- 发现登录或验证页面后，任务进入 `needs_attention`，等待用户在专用 Chrome 中人工处理。
- 当前工作单元和候选索引不得在暂停时标记完成；恢复后从原断点继续。
- 不改变手机号有效性、详情页证据、跨任务去重或 ERP 指纹账本规则。

## 方案

### 页面状态检测

搜索结果等待、详情等待和新详情页等待在每次轮询及超时边界都检查可见文本、页面标题、URL 和验证相关 DOM。明确命中登录或验证标记时抛出 `LoginRequired` 或 `ChallengeRequired`，不再降级为普通超时或空结果。

### 连续异常熔断

Provider 记录连续可疑失败。结果超时、页面没有正常结果/无结果标记等可疑状态累计到 2 次时，抛出 `ChallengeRequired`，让采集服务沿既有 `ProviderPaused` 链路暂停当前工作单元。正常完成一次搜索后清零连续异常计数。

### 自适应访问节奏

默认每 4 次搜索进入一次长冷却。普通搜索保持随机间隔；发生可疑失败后按连续失败次数逐级放大下一次等待，并使用更长的异常冷却。连续正常搜索后恢复默认节奏。

### 恢复语义

暂停时不推进当前工作单元。用户人工处理高德验证并点击“继续”后，任务重新执行当前工作单元，而不是从下一个关键词开始。

## 测试

- 搜索结果超时时页面出现验证标记，必须抛出 `ChallengeRequired`。
- 连续两个普通结果超时触发 Provider 熔断暂停。
- 正常搜索会重置连续异常计数。
- 异常后的下一次访问采用放大的等待时间。
- `ProviderPaused` 仍由采集服务保存为 `needs_attention`，当前工作单元保持可恢复。
