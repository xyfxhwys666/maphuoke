# 深圳 100 条高德电话线索与 CityProspect 布局设计

## 背景

MapSearch 已具备自然语言规划、公开网页发现真实公司全称、按城市和公司全称查询高德网页、保存高德最终字段以及 ERP 推送能力。当前页面虽然包含任务队列、需求输入、执行进度、推送设置和结果表，但结果表仍位于工作台内部，页面层级与 CityProspect 不一致。现有真实小样本也只能证明链路可用，尚未满足深圳 100 条带公开联系电话的交付目标。

本次增量只使用公开网页发现候选公司名称，并以高德网页作为最终公司名称、电话、地址、分类、坐标、POI 和来源链接的权威数据源。默认自然语言链路不得访问豆包聊天网页，也不得用公开网页摘要中的电话替代高德电话。

## 成功标准

1. 页面结构与 CityProspect 一致：任务队列和需求编辑器在顶部，执行状态、城市进度和 ERP 推送设置位于中部，采集结果是页面最后一个全宽区块。
2. 用户输入“我是做家具的，寻找全案软装公司、设计公司和整装公司，需要手机号码，尽量多找。”并限定深圳后，系统可持续拓展和采集。
3. 有效记录必须是高德精确匹配的最终公司记录，并且高德公开了符合 `^1[3-9]\\d{9}$` 的中国大陆 11 位手机号码。座机、400 电话、脱敏号码和格式不合法号码均不得计入 100 条有效信息。
4. 有效记录按规范化公司名称、规范化手机号和高德 POI 去重，累计达到 100 条后停止。
5. 页面能显示有效数、无电话数、拒绝数、候选耗尽状态和每条记录的高德来源；不伪造、不补写和不推断电话号码。
6. 自动化测试、前后端构建、真实高德采集和桌面/移动端界面验收均有当前证据。

## 方案选择

采用“按 CityProspect 重排并增强现有链路”的方案。

- 不采用仅靠 CSS 改顺序的方案，因为它保留了错误的 DOM 所属关系，后续结果表、筛选和批量操作仍会被主工作台网格约束。
- 不采用独立结果页，因为用户明确要求采集结果位于当前页面最下面。
- 不重写现有 Provider 和任务模型；本次沿用已有两段式边界，只增强候选覆盖、有效计数和耗尽处理。

## 页面结构

`CollectionWorkbench` 保留单一页面，并拆成两个顺序明确的视觉区域：

1. `collection-workspace`：任务队列、自然语言编辑器、执行计划、操作按钮、统计、城市进度和 ERP 接收设置。
2. `collection-results`：紧随工作区之后，是 `collection-shell` 的最后一个业务子区块，占满可用宽度。

结果区复用 CityProspect 的信息密度和交互顺序：标题与有效数量、城市筛选、结果表、推送状态、单条人工推送。批量推送按钮与接收 URL 仍在中部 ERP 设置区，结果行保留单条推送按钮。结果表在窄屏内横向滚动，页面本身不得产生横向溢出。

结果区至少展示：城市、公司名称、高德电话、地址、分类与坐标、公司名发现来源、高德链接、推送状态和操作。无电话行使用“未公开”和“仅展示”状态，不能启用推送按钮。

## 采集与数据流

### 1. 自然语言规划

解析城市为深圳市，目标公司类型为全案软装、设计和整装，并把“需要手机号码”映射成电话必填条件，把“尽量多找”映射成持续采集。用户目标数量设为 100 条有效记录，而不是 100 个候选名称或 100 个高德匹配结果。

初始关键词覆盖：

- 全案软装
- 软装设计
- 室内设计
- 家装设计
- 整装
- 全屋整装
- 装饰设计
- 住宅设计
- 别墅设计

扩展词必须保持家具业务的潜在客户语义，不能扩展成家具门店、家具厂家、建材供应商或无关工程公司。

### 2. 真实公司全称发现

公开网页发现器按“深圳 + 扩展关键词 + 公司”等查询发现真实公司全称，并继续翻页和切换关键词。候选必须包含可识别的正式企业名称，过滤榜单标题、问答句、泛行业词和营销标题。每个候选保存发现 URL、摘要、关键词和城市，但这些信息只作为公司名称候选证据。

候选按“城市 + 规范化公司名称”去重。某个关键词结果耗尽后进入下一个关键词；所有初始关键词耗尽且有效记录不足时，根据已命中的高德分类生成同义扩展词并继续发现。

### 3. 高德精确核验

每个候选使用“深圳市 + 公司全称”进入独立 Chrome 中已登录的高德网页搜索。只有城市一致且公司名称通过现有严格身份比较的 POI 才进入最终结果。相似名称、跨城市结果和无法识别的地图卡片均记为拒绝，不计入有效数。

最终字段只采用高德返回值：公司名称、手机号码、地址、分类、坐标、POI ID 和高德 URL。高德只公开座机或 400 电话时，可以保留公司、地址和地图来源供查看，但手机字段必须为空。公开网页电话、搜索摘要电话或推断号码都不得写入这些字段。

### 4. 有效计数与停止

`valid_contact_count` 只统计满足以下全部条件的记录：

- 高德精确匹配通过；
- 存在规范化后的中国大陆 11 位手机号码；
- 按公司名称、手机号和 POI 去重后仍为唯一记录。

达到 100 条后停止继续发现和高德查询，并将任务标记为完成。高德匹配但没有有效手机号的记录继续显示为 `display_only`，计入高德结果总数和无有效手机数，但不计入 `valid_contact_count`。座机和 400 电话不能启用批量或单条推送。

若全部关键词、翻页和同义扩展都耗尽后仍不足 100 条，任务以“数据源耗尽”结束，保留实际有效数和各类淘汰计数。该状态不得伪装成已完成 100 条。

## 状态与错误处理

- 高德要求登录、安全验证或验证码时，任务进入等待人工处理状态，保留当前候选索引和有效计数，恢复后从检查点继续。
- 单个公开搜索页、公司候选或高德详情失败时记录失败原因并继续下一项，不丢失已采集结果。
- 浏览器断开时暂停，不启动豆包聊天网页作为替代数据源。
- 后端或前端重启后，运行中任务按现有恢复机制重新排队，去重键和有效计数从持久化数据重建。
- ERP 推送失败不改变记录的高德有效性；推送状态单独展示并可重试。

## 测试设计

### 后端

- 自然语言请求生成深圳和目标行业关键词，并设置 100 条电话有效目标。
- 无有效手机号的高德记录不增加有效计数；座机和 400 电话不增加有效计数；11 位大陆手机号增加一次，重复公司、手机号或 POI 不重复计数。
- 达到 100 条立即停止；候选未耗尽前不会提前完成。
- 关键词和分页耗尽时进入明确的耗尽终态，并保留不足 100 条的真实数量。
- 公司全称发现与高德精确查询仍为两段式，默认路径不调用豆包聊天网页。
- 登录等待、任务恢复和 ERP 推送失败不破坏检查点或有效计数。

### 前端

- `collection-results` 在工作区、城市进度和 ERP 设置之后渲染，并且是页面最后一个业务区块。
- 结果标题显示高德结果总数和有效手机号数。
- 无有效手机号的记录显示但推送按钮禁用；有有效手机号的记录可单条或批量推送。
- 筛选、任务轮询和推送后结果合并继续工作。
- 390×844 和 1440×900 视口无页面级横向溢出，按钮和文字不重叠。

### 真实验收

1. 使用已登录的独立 Chrome 高德页面。
2. 提交深圳家具业务目标的自然语言需求并启动持续采集。
3. 监控候选数、高德匹配数、无电话数、拒绝数和有效数。
4. 抽查结果中的公司名称、电话、地址和链接与高德页面一致。
5. 只有累计至少 100 条带高德公开中国大陆 11 位手机号的唯一记录，才通过数量验收。
6. 在桌面和移动视口截图并检查结果区位于页面最底部、表格可读且无重叠。

## 非目标

- 不使用豆包聊天网页发现公司或补全联系方式。
- 不引入高德 API Key 作为本次交付前提。
- 不使用公开网页电话替代高德电话。
- 不修改 ERP 外部系统协议，继续使用现有 URL、Bearer Token、批量和单条推送能力。
- 不承诺深圳公开高德数据一定存在 100 条电话；若权威数据源真实耗尽，必须准确报告不足数量和证据，不能造数。
